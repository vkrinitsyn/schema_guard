# schema_guard_tokio 2.5.0

2026-11-22.

## New

- **Row access declared on a table.** A table's `security` says who reaches which of its rows -
  by a value the user's attributes are compared with. signon's labac gives a user, per attribute
  and action (select, insert, update, soft delete, delete), the values it may use.

  ```yaml
  - table:
      tableName: orders
      security: {schemaPath: [dept], alias: dept, softDelete: deleted_at}
  - table:
      tableName: order_items          # follows its order: a path of joins, the alias is the entity's
      security: {schemaPath: [public.order_items.order_id, public.orders.dept]}
  ```

- **`schemaPath` is a map of the table's named paths.** `dml` is the path to the attribute's
  value; every other name is a level of the row - `sal`, the security access level, or any name
  of the schema's own. A level is a second kind of access, ANDed with the first: the user's
  level of that name must be the same as or higher than the row's. A list is the short form of
  `dml` alone, and a table may be covered by levels alone.

  ```yaml
  security:
    schemaPath:
      dml: [public.docs.project_id, public.projects.dept]
      sal: [public.docs.project_id, public.projects.sal]
      review: [review_level]
  ```

- **The deploy decides what is made of the declarations**: `MigrationOptions::security`, a
  `SecurityMode`. `Off` (the default) ignores them. `Lsr(traversal)` registers the tables for
  ytproxy's SQL rewrite; with `Lsr(true)` the file is checked first - every step a column of a
  table of the same file, one-column primary keys, unique aliases. `Rls` enables and forces
  PostgreSQL's row-level security and makes a policy per action.
- **A hidden parent denies.** A row that follows a path through another declared table is
  reached only when that table's row is read too - also by the levels the following table does
  not declare, and also for a user with the action on every value of the attribute.
- **The SQL part** (schema `labac`), installed with the first declaration: the key table,
  `labac.enter(token)`, `labac.ids(alias, action)`, `labac.level(name)`,
  `labac.any_id(alias, action)` and the registry `labac.tables`.
- For a program that deploys table by table: `security::link` on the parsed file and
  `security::deploy_all` after its tables. `migrate` does both itself.
- The loader reads a database's declarations back from the registry (`PgTable.security`), and a
  declaration is written as it is read.

## Changed

- `MigrationOptions` has the field `security`. Built with `MigrationOptions::new()` or
  `default()` nothing changes; a struct literal names the new field.
- A table's `data` rows go in with FORCE lifted where the table's row-level security is forced.
